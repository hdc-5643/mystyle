## DateRangeSlicer v1.3.0.0（下拉弹层置顶 + 搜索框）

**用户反馈两个现象**：① 选择日期后列表不自动收回；② 下拉列表应「在顶层」（参照原生切片器白底黑字、蓝 checkbox、漂在所有视觉之上）。另提「全选项应随列表弹出」「单选/多选感觉没生效」。

**关键诊断**：先查了 `powerbi-models` 的 `BasicFilter` 构造函数（models.js L301-325）——它**会自动把数组参数拍平**（`if(Array.isArray(values[0])) _this.values=values[0]`），所以原先怀疑的"多选 In 嵌套数组导致失效"**不成立**。真正的根因是 **问题②的延伸**：弹层 `z-index:99999` 在 PBI 画布 stacking context 里没到顶，点击**穿透到后面的报表**，checkbox 收不到点击 → 看起来"没生效/不收起"；而点切片器其他区域能关，恰恰因为那次点击落在了报表上触发 document 关闭逻辑。

**修复**：
- `dateRangeSlicer.less`：`.drs-popup` 的 `z-index` 提到 `2147483647` + `transform: translateZ(0)` 强制独立 stacking context；新增 `body > .drs-popup` 全局兜底 `!important`；补搜索框 `.drs-popup-search*` 暗色样式。
- `src/visual.ts`：`openDropdown` 顶部加搜索框（输入即过滤下方列表 → `onSearchInput` 按 label/key 过滤行 `display:none`）；`capabilities.json` + `getFormattingModel` 加 `selection.searchEnabled`(默认 true) / `searchPlaceholder`(默认"搜索…")；`readSettings` 读取；`closeDropdown` 清搜索框引用。
- `pbiviz.json` 1.2.0.0 → 1.3.0.0（同 GUID `DateRangeSlicer20260825002`，本次为行为/样式微调非不兼容，不换 GUID）。
- `pbiviz package` 构建成功 → `dist/DateRangeSlicer20260825002.1.3.0.0.pbiviz`（45344B）；解包 manifest 校验：version=1.3.0.0、selection 含 searchEnabled/searchPlaceholder/showSelectAll、style.mode=between/dropdown 均正确。

**原生行为对齐结论（已写入 skill）**：单选模式点选项即收起；多选模式保持展开、连续勾选、点外部/Esc 收起（这就是原生，不是 bug）。"全选"行随列表弹出。"勾完即收"需开「单选」开关。

**经验固化**：自定义视觉里浮层"点了没反应/像没生效"先怀疑 z-index/stacking，别先查业务逻辑 —— 已补进 skill 弹出层置顶章节。

## 已发布 PBI 自定义视觉弹层实现调研（2026-08-25 接手人续作）

为对齐用户截图"原生切片器下拉漂浮在画布上"的视觉，调研了几个已发布开源 PBI 自定义视觉的弹层做法：

| 视觉对象 | 弹层做法 | 关键 |
|---|---|---|
| **powerbi-datepicker-slicer**（MauveOctopus729） | 浏览器**原生 `<select>` 元素** | OS 级渲染不进 DOM、不受 sandbox/overflow 裁剪，真漂浮；但只能单选、深色主题硬 |
| **微软官方 ChicletSlicer**（维护到 2026/8） | **根本不造弹层**——平铺按钮 + inline 搜索框 + 清除按钮，全挂 `this.root` | 没有 `document.body.appendChild`、没有 `position:absolute/fixed` 浮层 |
| **CalendarPro**（IAMBORG/CalendarPro，AppSource 认证） | React + **MUI `<Popover>`**（基于 Popper.js） | Portal 到 `document.body` + `fixed` + `zIndex:1000` + `ClickAwayListener`——跟我们现有实现**思路一致** |

**关键佐证**：CalendarPro 作者在 v2026.5.20.5 commit 亲口承认："Power BI's native placeholder renders outside the visual's iframe sandbox, so events on it never reach our handler regardless of how we attach the listener"——**已发布的 AppSource 认证视觉也接受 iframe sandbox 现实**，没真正漂浮到画布外。MUI Popover 看着"像浮"，是因为 Popper.js 把定位算得精，**让弹层不溢出 visual 容器边界（不被裁）**，视觉上像独立卡片。

**对 DateRangeSlicer 的启示**：CalendarPro 与我们现有实现架构思路一致（body+fixed+z-index+外部 click 关闭），差距只在 CalendarPro 用 Popper.js **自动避让边界**，我们手写 `top=rect.bottom; left=rect.left` 没避让。可引入 **`@floating-ui/dom`**（Popper.js 继任者，~5KB 纯 DOM 定位库）做边界避让，让弹层不溢出 visual 容器被裁，视觉接近原生——但仍不能真正飘出 iframe，这是 PBI 自定义视觉的客观边界。
